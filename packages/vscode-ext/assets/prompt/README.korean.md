# 어떤 프롬프트를 쓸까 — 고르고 나서 시작하자

*(English: `README.md` — `rtlgraph.language` 가 `auto` 이거나 `english` 일 때 함께 온다)*

여기 있는 것은 AI 에이전트에게 줄 완성된 지시문이다. 내용을 고치거나 복사해
붙일 필요는 없다. 붙여 넣는 건 **그 파일의 경로**와 **작업할 프로젝트 경로**
두 개뿐이고, 어떤 경로를 붙였느냐가 곧 무슨 일이 일어나는지를 정한다.

선반은 둘이다:

| | | |
|---|---|---|
| **`components/`** | 한 가지 일을 하는 프롬프트 일곱 | `spec` `rtl` `refactor` `rtlgraph` `assignment` `waveform` `codespec` |
| **`recipe/`** | 그 여섯을 **순서대로 엮은** 것 셋 | `assignment` `marking-day` `read-code` |

무엇을 할지 이미 알면 `components/` 에서 하나를 집고, **오늘 뭘 해야 하는지가 순서
문제**라면 `recipe/` 를 집어라 — 엮음이 프롬프트와 스크립트를 차례로 돌리고, 사람이
봐야 하는 자리(판정 직후, 코드 수정 전)에서 멈춘다.

```
RTLGraph: Copy Prompt Path        ← 갈래를 고르면 경로가 클립보드로
```

그 다음 에이전트(Claude Code, Codex, Cursor…)에:

```
/home/me/work/uart/.prompt/rtlgraph/components/assignment/korean.md 를 읽고 그대로 해줘.
PROJECT_FOLDER = /home/me/work/uart
```

각 프롬프트 맨 위에는 `이름 = <값>` 몇 줄이 있다. 프로젝트 경로, 명세 PDF 경로
같은 것만 채우고 나머지는 그대로 두면 된다.

---

## 여기서 시작

| 지금 눈앞에 있는 것 | 쓸 것 | 돌아오는 것 |
|---|---|---|
| 내가 쓴, 혹은 물려받은 RTL 을 **보고 싶다** | **`rtlgraph`** | 컴포넌트마다 회로도. 코드는 그대로 |
| **받은 스켈레톤** — 과제, 남의 저장소 — 을 손대면 안 된다 | **`assignment`** | 같은 것 + 테스트벤치, 명세가 PDF 면 상자마다 그 문장으로 가는 링크 |
| 동작은 하는데 구조가 엉망이고, 고쳐도 된다 | **`refactor`** | 세 층 구조로 재배치한 코드, 그 다음 회로도 |
| 명세는 있고 코드가 없다 | **`rtl`** | 그 명세대로 쓴 새 RTL, 시뮬레이션까지, 그 다음 회로도 |
| 아이디어만 있고 명세도 없다 | **`spec`** | 읽고 따질 수 있는 `SPEC.md`. 그걸 다시 `rtl` 에 준다 |
| 코드밖에 없고 **무엇을 하는 코드인지** 글로 정리해야 한다 | **`codespec`** | 깊이 여섯 단계 명세서 + 숫자를 잰 벤치 + 작업 기록 |
| 시뮬레이션은 이미 돌았고 **왜 그렇게 됐는지**가 궁금하다 | **`waveform`** | `waveform-analysis.md` — 덤프의 숫자를 코드로 설명, 체크마다 한 절 |

둘 중 뭘 써야 할지 애매하면 기준은 하나다 — **코드를 바꿔도 되는가?**
`rtlgraph` 와 `assignment` 는 절대 안 건드리고, `refactor` 와 `rtl` 은 건드린다.

---

## 하나씩

### `rtlgraph` — 있는 RTL → 회로도

평소에 쓰는 것. 에이전트가 Verilog 를 읽고 컴포넌트마다 그 폴더에
`*.rtlgraph.json` 을 쓰고, 쓴 걸 스스로 검증한다. 코드는 한 줄도 안 움직인다.

프로젝트가 내 것이거나, 최소한 폴더가 새로 생겨도 괜찮을 때 쓴다 — RTLGraph 의
표준 배치대로 파일을 놓기 때문이다.

끝난 뒤: 루트 파일을 열어 본다. 상자를 우클릭하면 그 상자가 나온 코드 줄로 간다.
`origin` 이 틀렸다면 검증기가 이미 말했을 것이다.

### `assignment` — 손대면 안 되는 스켈레톤

과제용, 또는 재배치할 권한이 없는 저장소를 읽을 때. **코드를 위한 폴더를 만들지
않고** 이름도 바꾸지 않는다. 배치는 둘 중 선택:

- `RTLGRAPH_FOLDER` 를 비워 두면 → JSON 이 각자 설명하는 모듈 옆에;
- 폴더 이름을 적으면(`rtlgraph` 같은) → RTLGraph 파일이 전부 그 폴더 하나에
  모이고, 코드 쪽은 완전히 그대로 남는다.

끝나고 나면 폴더 두 개가 남는다 — 조교가 준 것을 넣을 `tb/given/`, 에이전트가 쓴
것이 들어 있는 `tb/mine/` — 그리고 실행기 `.agent/rtlgraph/run-tb.sh`. 벤치 하나를 프로젝트
폴더 안으로 바꿔 넣고, 나머지 설계와 함께 돌리고, 판정 한 줄을 찍는다. 그래서 채점
벤치가 오는 날 할 일은 이것뿐이다:

```
cp ~/Downloads/tb_uart.v  <프로젝트>/tb/given/
<프로젝트>/.agent/rtlgraph/run-tb.sh given
```

인자 없이 돌리면 둘 다, `mine` 이면 네 것만, `--keep` 을 주면 마지막 벤치를 프로젝트
폴더에 그대로 남긴다(Vivado GUI 로 이어서 볼 때). 제출할 때가 되면
`.agent/rtlgraph/make-submission.sh` 가 핸드아웃이 요구하는 `.v` 만 모아서 elaborate 를 확인하고
zip 으로 만든다(무엇이 들어가는지 먼저 보려면 `--list`).
**처음부터 테스트벤치를 같이 받았다면 그 경로를 `GIVEN_TB` 에 적어라.** 에이전트가
그걸 받은 그대로 먼저 돌리고, 출력을 그대로 옮기고, 자기 벤치와 결과가 다르면 자기
쪽이 틀린 것으로 본다. 그 다음
**자기 벤치**도 요구한다 — 명세가 함의하는 엣지 케이스마다 하나, 각각 맨 위에
"무엇을 잡으려는 벤치인지" 적어서. 명세가 PDF 면
`source.spec` 과, 문서가 실제로 말하는 요소에 그 문장 인용까지. 그런 상자를
우클릭하면 도면 옆에 문서가 열리고 그 문장이 하이라이트된다.

코드가 자기 안에 없는 기본 소자(`DFF` 가 흔하다)를 쓰면, 같이 복사된 `.base/`
폴더를 `source.lib` 로 가리킨다.

### `refactor` — 구조를 바꾸고, 그 다음 그린다

코드를 다시 쓰는 유일한 프롬프트. 일부러 따로 뒀다 — 구조를 바꾸는 것과 그리는
것은 다른 결정이고, 하나만 시킬 수 있어야 하니까. 먼저 동작 기준선(baseline)을
기록하고, `comb/ control_path/ data_path/ seq/` 로 재배치하고, 그 기준선과 다시
비교한 뒤에야 RTLGraph 파일을 다시 만든다.

과제에는 쓰지 말 것.

### `rtl` — 명세 → 새 RTL

명세 문서로 모듈과 테스트벤치와 RTLGraph 파일을 쓴다. 시뮬레이터가 필요하고,
이 컴퓨터에 뭐가 있는지는 `.agent/rtlgraph/ENVIRONMENT.md` 가 말해 준다.

### `waveform` — 일어난 일 → 왜 일어났는지

코드가 아니라 **시뮬레이션에서 시작하는** 유일한 프롬프트. 먼저
`.agent/rtlgraph/run-tb.sh --wave` 를 돌린다 — 어떤 테스트벤치도 고치지 않고 파형을
덤프해서 `waveform/<given|mine>/<벤치>.vcd` 와 `<벤치>.waveform.json`(에이전트와 뷰어용)을
쓴다. 같은 숫자를 글로도 읽고 싶으면 `--report` 를 붙여라 — 그때만 사람용
`<벤치>.waveform.md` 가 함께 나온다. 클럭 주기, 리셋이
풀린 시각, 그 뒤에도 미정의였던 신호, 핸드셰이크가 언제 성립했는지, 그리고 벤치가 찍은
체크 하나당 구간 하나로 자른 실행 전체.

여기까지가 **측정**이다. 이 프롬프트는 나머지 절반을 시킨다: 그 파형을 만드는 설계의
줄이 어디인지, 각 체크가 왜 통과했는지, 실패하려면 무엇이 틀려야 하는지. 숫자는 전부
덤프에서 가져오고 주장마다 코드를 인용하라고 못 박아서, **믿는 게 아니라 확인할 수 있는**
분석이 되게 했다. "Vivado 를 굳이 열어서 봐야 하나?"에 대한 답이기도 하다 — 읽으려는
목적이면 대개 아니고, 실패를 디버깅할 거면 여전히 그렇다.

### `codespec` — 코드 → 읽을 수 있는 명세서

아무도 문서를 안 남긴 코드, 또는 받은 스켈레톤을 **글로 다시 쓰는** 것. 코드는 한 글자도
건드리지 않고 `<폴더>/spec/` 에 모듈 하나당 한 파일을 쓴다. 핵심은 **깊이를 섞지 않는
것**이다 — 1 절(하는 일, 신호 이름 없이)만 읽고 덮어도 틀린 그림이 남지 않고, 6 절까지
가면 신호 하나하나의 쓰임과 곁가지 효과가 있다.

숫자에는 출처가 붙는다(`시뮬`/`계산`/`읽기만`), 문장에는 주인이 붙는다(`[PDF]`/`[코드]`/
`[미정]`). **`[미정]` 이 제일 값어치 있다** — 핸드아웃이 말하지 않아 코드가 알아서 정한
것들, 즉 아무도 승인한 적 없는 결정 목록이다. `sim/` 에는 판정하지 않고 사이클만 찍는
벤치를 두어 "사이클 10851 에 valid" 같은 문장이 측정값이 되게 한다.

### `spec` — 아이디어 → `SPEC.md`

아이디어가 아직 머릿속이나 문단 하나로만 있을 때. **Decisions**(정해야 해서 정한
것과 그 이유)와 **Open questions**(못 정한 것) 절이 있는 명세를 만든다. 이 두 절을
먼저 읽어라 — 오해는 거기 있다 — 그 다음 결과를 `rtl` 에 준다.

## 엮음 셋, 하나씩

엮음은 여섯 중 여러 개를 **순서대로** 도는 한 장짜리다. 타자를 아끼는 게 아니라,
**순서와 멈출 자리가 글로 적혀 있다**는 것이 값어치다 — 제일 틀리면 안 되는 순간에
그걸 머리로 기억하지 않아도 된다.

규칙은 셋. 한 단계가 실패하면 거기서 멈춘다(통과하지 못한 실행의 "왜 통과했나"는
의미가 없다). **⏸ 가 사람이 봐야 하는 자리**다 — 판정 직후, 그리고 코드가 바뀌기
전. 맨 위 변수는 한 번만 채우면 아래 프롬프트들이 물려받는다.

### `recipe/marking-day` — 점수를 정하는 벤치가 방금 도착했다

```
tb/given/ 에 벤치가 있나?  →  run-tb.sh given  →  ⏸ 판정  →  run-tb.sh given --wave
                                                          →  components/waveform
```

메일이 왔을 때 집는 것. `tb/given/` 이 비어 있으면 **가짜 벤치를 만들지 않고** 멈추고,
판정을 무엇보다 먼저 옮기고 거기서 선다 — FAIL 이면 무엇을 할지는 네가 정하고, 그동안
에이전트는 아무것도 고치지 않는다. 그 다음 그 실행만 덤프해서 **조교 벤치 하나에 대해서만**
분석을 쓴다. 나머지는 나중에 해도 되지만 그건 안 된다.

### `recipe/assignment` — 과제를 처음부터 제출 직전까지

```
components/assignment  →  run-tb.sh mine  →  ⏸ 판정 + 검증기
                       →  run-tb.sh --wave  →  components/waveform
                       →  make-submission.sh --list  →  ⏸ 무엇이 들어가는지
```

시작하는 날의 긴 것. 회로도를 그리고, 벤치를 `tb/mine/` 에 쓰고, `tb/given/` 은 비워
두고, 파형마다 설명을 쓰고, 제출물은 **목록만** 보여준다 — **zip 은 네가 말하기 전에는
만들지 않는다.** 두 번 멈춘다: 벤치가 돈 뒤(벤치가 틀렸는지 설계가 틀렸는지는 에이전트가
아니라 네가 정한다), 그리고 제출 전.

### `recipe/read-code` — 남의 RTL 을 이해해야 한다

```
components/rtlgraph  →  ⏸ 검증기 + 하나의 생각  →  run-tb.sh --wave
                     →  components/waveform
```

그림과 글만 쓴다 — `.v` 는 이 엮음 내내 읽기 전용이고, 이상해 보이는 것은 코드가 아니라
마지막 보고에 적는다. 한 번 멈추면서 **이 설계를 성립시키는 하나의 생각**을 한 문장으로
요구한다. 그 문장이 안 써지면 그 아래는 아직 읽을 값어치가 없다. 벤치가 하나도 없으면
거기서 멈추고 그렇게 말한다 — 벤치를 새로 쓰는 것은 이 엮음의 일이 아니다.

## 결과를 바꾸는 두 가지

**언어.** `rtlgraph.language` 가 가리키는 언어만 복사된다 — 한국어로 두면 폴더마다
`korean.md` 하나뿐이고, `auto` 면 `korean.md` 와 `english.md` 가 둘 다 온다. 시키는 일은 같고,
`meaning`·라벨·보고를 어느 언어로 쓰는지가 다르다. 코드에서 온 이름은 어느
쪽이든 번역하지 않는다.

**설치된 것.** `.agent/rtlgraph/ENVIRONMENT.md` 는 `RTLGraph: Copy Agent Spec to Workspace`
를 돌릴 때마다 다시 만들어지고, 프롬프트는 그걸 따른다: 어떤 시뮬레이터를 쓸지,
그리고 NodeGraph 검증 지도를 쓸지 말지(그 확장이 설치돼 있을 때만). 나중에 도구를
설치했다면 명령을 다시 돌려 보고서를 갱신해라.

## 에이전트가 끝났다고 하면

1. **받은 테스트벤치 결과부터 읽어라**(있었다면). 점수를 정하는 건 그것이고,
   나머지는 그 주위의 근거다. (`run-tb.sh --wave` 를 붙이면 `waveform/` 에 파형과
   측정값이 남고, `--report` 까지 주면 `waveform.md` 도 나온다 — PASS 가 말해 주지
   않는 숫자들: 유지 시간, 대기 시간, 리셋 후에도 미정의였던 신호.)
2. **검증기 줄을 읽어라.** 기준은 `0 errors`. 경고는 코드에 대한 진짜 발견이거나
   에이전트가 고쳤어야 할 것 중 하나고, 어느 쪽인지 말하게 되어 있다.
3. **루트 `*.rtlgraph.json` 을 열어라.** 답은 그림이고, JSON 은 저장 방식일 뿐이다.
4. **상자 하나를 코드와 대조해라.** 우클릭 → *Open the Code*. 그 줄이 맞으면
   나머지도 대개 맞다.
5. **마음에 안 들면 직접 배치해라.** 옮기고 크기 바꾸고 선을 꺾은 것은 전부
   `layout` 에 저장되고, 에이전트를 다시 돌려도 그대로 남는다.
