# 배선(routing) — 우리 방식과 Digital Logic Sim 방식

이 문서는 두 가지를 적는다. 우리 라우터가 **어떤 원리로** 선을 긋는지, 그리고
[Sebastian Lague의 Digital Logic Sim](https://github.com/SebLague/Digital-Logic-Sim)(이하 DLS)은
어떻게 하는지. 마지막 절은 우리가 실제로 저지른 실수와, 다시 그러지 않게 막아 두는 규칙이다.

구현은 `packages/rtl-layout/src/index.ts` 한 파일에 있다.

---

## 1. 근본 차이 — 누가 선을 긋는가

| | RTLGraph | Digital Logic Sim |
|---|---|---|
| 선을 긋는 주체 | **프로그램**이 매번 새로 계산 | **사람**이 클릭으로 꺾어가며 그림 |
| 저장되는 것 | 넷의 양 끝(`driver`, `sinks`)뿐. 좌표는 저장하지 않음 | 사용자가 찍은 중간 꺾임점 목록 |
| 부품을 옮기면 | 전체를 다시 계산 | 끝점만 따라가고 중간 꺾임은 그대로 (선이 늘어남) |
| 겹침 회피 | 있음(채널·트랙·라이저) | **없음**. 겹치면 겹친 채로 둠 |
| 경로 단순화 | 있음(정리 단계) | **없음**. 같은 직선 위의 점 세 개도 그대로 남음 |

DLS에는 자동 배선이 아예 없다. A\*도, 직교 라우터도, 장애물 회피도 없다. 사람이 그리기
때문에 필요가 없다. 그래서 **경로 탐색 쪽에서 베낄 것은 없고**, 배울 것은 데이터 모델과
그리는 방식, 그리고 시선을 어디로 모으는가에 있다.

---

## 2. 우리 원리 — 행과 채널

슬라이드 p.31의 관례를 그대로 따른다. 회로도는 가로줄(행)로 쌓이고, 선은 행 **사이의
통로(채널)** 로만 지나간다.

```
채널 0     ── 트랙들 ──
행 0       제어 블록 · 가장 깊은 조합 논리(MUX)
채널 1     ── 트랙들 ──
행 1       조합 논리 깊이 1 (+1, ADD, SUB)
채널 2     ── 트랙들 ──
행 2       레지스터
채널 3     ── 트랙들 ──
행 3       출력 포트
```

순서대로 이렇게 만든다.

1. **모양 정하기** (`shapeOf`) — 상자 크기와 핀이 어느 변에 붙는지. 레지스터는 D 위·Q 아래,
   연산은 입력 아래·출력 위, 제어 신호는 왼쪽(레지스트리 결정 R2).
2. **행 배정** — 조합 깊이만큼 위로 올린다. 레지스터는 맨 아래 행, 제어 블록은 0행.
3. **열 배치** — 데이터로 이어진 이웃의 무게중심(barycenter)으로 8회 정렬하고, 겹치지 않게
   민다(`relax`). 그 뒤 **압축**: 모든 행이 공통으로 남긴 여유만큼 한 번에 왼쪽으로 당긴다(L12).
4. **나가는 방향 정하기** (`dropsDown`) — 상자 한 변의 핀들은 같은 방향으로 빠진다. 대상이
   같은 행이면 **아래 채널**로 통일한다(L11). 양쪽이 같은 통로를 고르면 잇는 수직선이 필요 없다.
5. **드롭** — 좌우 핀은 상자 옆 `PITCH` 간격의 세로선으로 채널까지 내려가거나 올라간다.
   방향 쪽에 가까운 핀이 상자에 더 붙는 x를 받아, 드롭끼리 서로 가로지르지 않는다.
6. **라이저** — 여러 채널에 걸친 넷은 세로선 하나로 잇는다. 상자·다른 드롭·다른 라이저가
   없는 x를 고르고, 자기 넷의 스텁과 x가 같으면(=곧게 이어지면) 비용을 깎아 우선한다(L10).
7. **트랙** — 채널 안에서 가로선들이 겹치지 않게 구간 색칠로 층을 나누고, 위에서 내려오는
   스텁이 아래에서 올라오는 스텁과 같은 x에서 겹치지 않도록 위상 정렬한다(L4).
8. **정리** (`tidyWires`) — 다 그린 뒤, 마주 보는 두 핀은 직선(또는 한 번 꺾기)으로 바꾸고,
   긴 직선 사이의 몇 px짜리 층계는 끝으로 밀어 없앤다. **바꾼 경로가 상자·다른 넷과 겹치지
   않을 때만 채택한다**(L16).

핵심 성질: **좌표는 IR에 없다.** 노드 ID는 코드에서 온 이름이고(D1), 배치는 열 때마다
다시 계산한다. 그래서 에이전트가 JSON을 다시 써도 사용자가 보던 그림이 깨지지 않는다.

## 3. DLS가 하는 것 중 우리가 가져온 것 / 안 가져온 것

조사한 파일: `Assets/Scripts/Game/Elements/WireInstance.cs`,
`Graphics/World/WireLayoutHelper.cs`, `WireDrawer.cs`, `DevSceneDrawer.cs`,
`Game/Helpers/GridHelper.cs`.

**가져온 것**

- **둥근 끝·둥근 모서리** (X8). DLS는 선분마다 캡슐(SDF)을 그리고, 겹치는 둥근 끝이 모서리를
  이어준다. 별도의 모서리 계산이 없다. SVG에서는 `stroke-linecap/linejoin="round"` 두 속성이
  같은 일을 한다.
- **끝점은 저장하지 않고 핀에서 계산.** DLS의 `GetWirePoint`는 0번과 마지막 점을 가로채
  핀 위치를 그때그때 돌려주고, 저장할 때는 그 자리에 0을 쓴다. 부품을 옮겨도 파일이 더러워지지
  않게 하려는 것. 우리는 아예 좌표를 저장하지 않으니 같은 성질을 더 강하게 갖는다.
- **시선은 순서로 모은다.** DLS는 흐리게 하지 않는다. 신호가 흐르는 선, 굵은 버스, 지금
  편집 중인 선을 **위에 그린다**(`WireDrawOrder`). 교차점에서 끊기지 않는 쪽이 눈에 잡힌다.
  우리도 강조된 것을 위에 그린다(V6).

**안 가져온 것 (지금은)**

- **버스는 굵은 선이 아니라 여러 가닥.** 8비트면 8줄을 나란히 긋고, 짝수 가닥만 아주 살짝
  밝게 해서 셀 수 있게 한다. 모서리는 가닥마다 offset 직선의 교점으로 깎고(miter), 각도가
  급해지면(dot < −0.75) 부호를 뒤집어 폭발을 막는다. 우리는 굵기 + 숫자 라벨을 쓴다.
- **모서리 필렛(둥글게 깎기).** DLS에도 코드는 있지만 호출되지 않는다(`DrawWireCurved`).
  규칙만은 참고할 가치가 있다: 반경은 고정값이되 **양옆 선분 길이의 절반을 넘지 않게** 자른다.
  짧은 층계에서 반경이 넘치는 것을 막는 방법이다.
- **격자 스냅·직각 고정.** 사람이 그릴 때만 필요하다. `ForceStraightLine`은 더 긴 축만 남기는
  한 줄짜리 투영이다.

## 4. 우리가 저지른 실수와, 다시 막는 규칙

같은 함정을 다시 밟지 않으려고 적어 둔다. 괄호 안은 그걸 잡아 두는 테스트다.

| 증상 | 원인 | 지금 규칙 |
|---|---|---|
| 대각선이 그어짐 | 포트를 핀 옆에 붙일 때(hug) 그 넷을 읽는 곳이 더 있는지 확인하지 않아, 채널 배선을 건너뛰고 두 점을 곧장 이었다 | 붙이기는 **그 포트가 넷의 유일한 사용처일 때만**. 붙인 선도 x·y가 다르면 한 번 꺾는다 (`demo/* lays out cleanly on its own`) |
| 포트 알약이 서로 겹침 | DFF의 `RST`·`EN` 핀 간격은 8px인데 알약 높이는 18px | 붙이기는 **그 변의 핀 간격이 포트 상자보다 넓을 때만** |
| 프레임 핀이 9px 간격으로 붙음 | 자식의 입력 포트들이 같은 행에 쌓여 같은 y를 가짐 | 제어 블록 옆에 붙는 입력이 있으면, 같은 행으로 가던 다른 입력은 **한 행 아래**로 (L15) |
| 머리핀(스텁 옆에 바로 붙는 라이저) | 같은 행의 두 상자가 위/아래 통로를 각자 골랐다 | 같은 행으로 가는 핀은 **모두 아래 통로** (L11, `a net between two boxes of one row takes one channel`) |
| 펼치면 폭이 2.6배로 늘어남 | 정렬 반복이 이웃 쪽으로만 밀어서, 서로만 참조하는 무리가 오른쪽에 굳었다 | 마지막에 **모든 행 공통 여유만큼 왼쪽으로 압축** (L12) |
| 상자보다 긴 U자가 위로 | 제어 블록 때문에 행이 높은데 상자가 행 바닥에 붙어 있었다 | 조합 논리 상자는 **행 위쪽**에 건다 (L13) |
| 프레임 사이 깊은 U자 | 라우터는 "핀 → 통로 → 핀"만 안다 | 다 그린 뒤 **검증 후 교체**하는 정리 단계 (L16). 계획 단계에서 특수 규칙을 넣었더니 겹침이 생겨 되돌렸다 |
| `+1`·`ADD`가 통째로 사라져 보임 | 흐린 것을 전부 맨 아래에 깔았더니 나중에 그린 **틀 배경이 덮었다** | 투명 처리는 **같은 층 안에서만** 아래로 (V6) |
| 필터가 배선을 반쪽만 남김 | 숨기기 정책 | 숨기지 않고 **투명도만 높인다** (V4) |
| Inkscape에서 검은 사각형 | 클릭 영역을 `fill="transparent"`로 그림. SVG 1.1에 없는 값 | 칠하지 않고 CSS `pointer-events`로 클릭만 받는다 |

**배운 것 한 줄.** 경로 문제는 계획 단계에서 특수 규칙을 늘리는 것보다, **다 그린 뒤 더 나은
경로를 제안하고 검증해서 교체**하는 편이 안전하다. 검증(상자 통과·다른 넷과 겹침)이 항상
붙어 있으면 새 규칙이 기존 그림을 망가뜨릴 수 없다.
