# 설계 결정

마일스톤을 만들며 초안(`tmp/draft/03-EXTENSION-PLAN.md` §4, §7, §13)의 미해결 사항 중
필요한 것을 확정했다. 근거가 NodeGraph 교훈이면 그렇게 적었다.
나머지 질문(시스템 뷰, 재추출 트리거, bridge 기본값 등)은 해당 마일스톤에서 정한다.

## 프로젝트 구조 — 컴포넌트는 폴더로 늘어난다

설계는 main component 하나를 먼저 잡고 그 폴더 안에 `comb/data_path`, `comb/control_path`,
`seq`, `tb` 층 폴더를 미리 만든 뒤 채운다(`02` §2). 고정된 이름은 **층 폴더와 `base/` 뿐**이다.
컴포넌트의 이름·개수·중첩은 설계마다 다르다 — 초안의 host/device 는 예시일 뿐이다.
"자기 `seq/` 를 가진 디렉토리 = 컴포넌트" 이고, 하위 컴포넌트는 필요해질 때 부모 폴더 안에
생긴다. **컴포넌트가 하나뿐이어도 main component 폴더를 만든다**(사용자 결정, 아래 H1).
코드와 IR 어디에도 특정 컴포넌트 이름은 없다.

## IR (`packages/rtl-ir`) — M0

| # | 결정 | 이유 |
|---|---|---|
| D1 | **노드 ID = 컴포넌트 TOP 기준 인스턴스 경로** — `CNT_FF`, `data_path.u_inc`, `data_path.u_ch0.u_add` | 줄번호·순번 ID 는 재추출마다 바뀌어 `layout` 병합이 불가능하다. NodeGraph 는 순번 ID 를 끝내 못 고쳤다. 경로라서 같은 모듈을 여러 번 써도 유일하다 |
| D2 | **포트 노드 ID = `@NAME`**, 엔드포인트도 포트명 없이 `@NAME` | `@` 는 Verilog 식별자에 못 오므로 인스턴스와 충돌하지 않는다 |
| D3 | 포트 노드는 `time` 이 없다 | 초안 예시의 `time: "port"` 가 `{comb, seq}` 규칙과 모순이었다 |
| D4 | 엔드포인트 = `<노드ID>:<포트>` | 마지막 `:` 로 자르므로 ID 의 `.` 과 충돌 없음 |
| D5 | **층 모듈 평탄화** — `comb/data_path` 모듈은 인스턴스로 펼치고(래퍼는 노드 아님), `comb/control_path` 모듈은 `control` 노드 하나(진리표) | 슬라이드 p.31 그림이 dp 내부 상자를 그리고 cp 는 표로 뺀다 |
| D6 | 서브모듈 내부 전용 신호는 경로 접두 — `data_path.ADD_OUT` | 채널을 복제하면 이름이 겹친다 |
| D7 | TOP 의 단순 배선 `assign` 은 신호를 새로 만들지 않고 `aliases` | `assign OUT_D = ACC_D` 는 같은 넷. 넷마다 드라이버가 정확히 하나라는 C6 이 유지된다 |
| D8 | 상수 연결은 `consts` — `EN: "1'b1"` | 신호가 아니지만 입력이 연결됐다는 사실은 남아야 한다 |
| D9 | **파생 가능한 값은 IR 에 넣지 않는다** — 노드 폭(`params` + registry), MUX 입력 순서(registry). 초안의 `sel`/`inputs`/`width`/`rst`/`en` 필드 제거 | 같은 사실이 두 곳에 있으면 어긋난다. NodeGraph 의 `nodeNaturalY` 누적 오차 교훈 |
| D10 | `component` 는 선택 필드. 없으면 파일 자신의 컴포넌트 | 위 "프로젝트 구조" 참고 |
| D11 | 파일에 `kind` 명시 — schematic 은 `"component"`, 루트는 `"system"` | 둘을 한 스키마·검증기로 다룬다(H2) |
| D12 | `origin` = 인스턴스 문장 줄. 진리표는 `truthTable.origin` = `casex` 줄 | 골든 테스트가 실제 소스 줄과 대조한다 |
| D13 | 신호 `flow` — 클럭 입력 넷 `clock`, 1차 리셋 입력 넷 `reset`, 제어 경로 출력(리셋 제어 포함) `control`, 나머지 `data` | `CNT_RST` 같은 리셋 제어는 진리표 출력이므로 제어선으로 보인다 |
| D14 | `layout = { grid?, nodes: {id: {x,y}}, collapsed?: [groupId] }` | 초안의 `_meta` 처럼 예약 키를 노드 맵에 섞지 않는다. 그룹 정의(`groups`)는 재추출 대상, 접힘 상태는 사용자 것 |
| D15 | `view` 는 선택. 병합 시 이전 값 유지 | 보기만 해도 파일이 dirty 가 되던 NodeGraph 문제를 M2 에서 피한다 |
| D16 | 검증은 예외 대신 진단 목록 반환 | 부분 추출 + 진단 표시(`02` §11 Q5) |

## 뷰 필터 (`packages/rtl-ir/src/view.ts`) — M1

| # | 결정 | 이유 |
|---|---|---|
| V1 | 프리셋 6개(`all` `datapath` `controlpath` `comb` `registers` `fsm`)를 `rtl-ir` 에 둔다 | 에디터와 내보내기가 같은 규칙을 쓴다 |
| V2 | clock·reset 넷은 control 흐름 | 흐름에 세 번째 값을 만들지 않는다 |
| V3 | 숨김 정책 `hide` — 드라이버와 싱크 하나 이상이 보여야 넷을 그린다. 포트 노드는 연결된 넷이 보일 때만 | `datapath` 프리셋 결과가 슬라이드 p.31 요소와 정확히 같다(테스트). `bridge` 는 M2 |
| V4 | 필터는 **지우지 않고 강조한다** — 고르지 않은 것은 **색을 바꾸지 않고 투명도만 높인다**(`dim` 클래스 + `opacity` 0.18). 편집기와 내보내기 모두 같다 | 사용자 요구. 숨기면 넷의 한쪽 끝만 남아 배선이 잘려 보였고(`comb` 에서 `inbuf` 가 빈 상자가 되는 문제), 구멍 뚫린 회로도보다 회색 배경이 읽기 쉽다 |
| V5 | 무엇을 고르는지 — 논리 상자는 **자기 그룹이 켜져 있고 그 안에서 자기 종류가 선택됐을 때**, 넷은 그 넷이 잇는 논리 상자가 모두 선택됐을 때, 포트·컴포넌트 상자는 선택된 넷이 닿을 때. 논리 상자에 닿지 않는 넷(컴포넌트끼리)은 흐름 축만 본다 | comb/seq 는 논리의 성질이라 컴포넌트 경계를 넘는 넷에는 적용할 수 없다 |
| V6 | 투명해진 것은 **같은 층 안에서** 강조된 것 아래에 그린다. 전체를 한 번에 깔면 나중에 그려지는 틀 배경이 덮어버린다 | 실제로 겪은 버그: `+1`·`ADD`·제어 블록이 통째로 사라져 보였다 |
| V7 | 필터는 **2단 트리** — `{ comb: Flow[], seq: SeqKind[] }`. Comb 아래 data/control, Seq 아래 reg/fsm. 레지스터 판정: `time: "seq"` 인 `reg` 중 `fsm` 파일을 가리키거나 `flow: "control"` 이면 FSM 레지스터 | 사용자 요구, D02 "Top module illustration"(Registers · Data-path · Control-path · Registers for FSM)과 같은 구분. 2축 격자로 두면 레지스터의 "control" 과 논리의 "control" 이 같은 버튼이 되는데, 둘은 다른 뜻이다. IR 의 `time` 은 그대로 두고 보기 쪽만 나눈다 |
| V8 | 예전 평면 필터 `{flow, time}` 은 트리로 읽어 들인다 — `time` 에 `comb` 이 있으면 `comb = flow`, `seq` 종류는 짝이 되는 흐름(data→reg, control→fsm)이 있을 때만 켠다. 옛 `time: "seq"` 는 `reg`+`fsm` 둘 다를 뜻한다 | 작업영역에 남아 있는 상태가 갑자기 빈 화면이 되면 안 된다. 이 규칙으로 옛 6개 프리셋이 새 프리셋과 정확히 같아진다(테스트) |
| V9 | 그룹 버튼(Comb·Seq)을 눌러야 그 아래 종류 버튼이 살아난다(꺼져 있으면 비활성·흐리게). 그룹은 **마지막 하나가 꺼지지 않고**, 그룹 안에서도 마지막 종류는 남는다 — 종류를 다 끄고 싶으면 그룹 버튼을 끈다 | 사용자 요구. 아무것도 강조되지 않는 상태(둘 다 꺼짐)는 화면이 통째로 흐려질 뿐 정보가 없다 |
| V10 | 넷의 흐름 축은 **선택된 종류에서 유도한다** — data 는 `comb.data` 또는 `seq.reg`, control 은 `comb.control` 또는 `seq.fsm` 이 켜져 있을 때 | 레지스터는 자기가 속한 경로 위에 있다(D02: 데이터 레지스터는 데이터 경로, 상태·제어 레지스터는 제어 경로). 이렇게 두면 `datapath`·`controlpath` 프리셋 결과가 예전과 같다 |

## 레이아웃 (`packages/rtl-layout`) — M1

| # | 결정 | 이유 |
|---|---|---|
| L1 | **행 = 조합 깊이** — 레지스터 맨 아래, 조합 논리는 입력 쪽 깊이만큼 위로, 제어 블록은 맨 위 행 왼쪽, 출력 포트는 레지스터 아래 | 슬라이드 p.31 |
| L2 | 열 순서는 데이터 넷으로 연결된 이웃의 barycenter 로 8회 교대 정렬, 겹치지 않게 당겨 배치 | 결정적이고 작은 설계에 충분. NodeGraph 의 greedy 재배치가 흔들렸던 교훈으로 매 실행 같은 결과를 테스트 |
| L3 | **배선은 직교 채널 라우팅** — 핀은 옆 채널의 트랙으로 나가고, 여러 채널에 걸친 넷은 상자·스텁·다른 라이저가 없는 x 의 수직 라이저로 잇는다 | 회로도 관례. NodeGraph 의 격자 A* 는 결국 대부분 지워졌다 |
| L4 | 채널 안 트랙은 구간 색칠 후, 위에서 내려오는 스텁이 아래에서 올라오는 스텁과 같은 x 에서 겹치지 않도록 위상 정렬 | 테스트가 실제로 잡은 겹침 버그의 수정 |
| L5 | 좌우 핀은 박스 옆 드롭으로 빠지고, 한 변의 드롭은 연결 대상이 대부분 아래면 아래 채널로 | 제어선이 위로 올라갔다 곧바로 내려오는 지그재그 제거 |
| L6 | 핀 하나에만 연결된 포트는 채널을 쓰지 않고 그 핀 옆에 붙인다 | `RST/SHOW/MODE → acc_cp`, `OUT_FF → ACC` 가 직선 |
| L7 | 숨김(`hidden`) 넷은 라우팅하지 않고, 그 넷뿐인 포트는 상자도 없다 | `CLK` |
| L8 | **필터와 무관하게 전체를 배치**한다. 렌더러가 기본으로 보이는 부분에 맞춰 잘라내고, 에디터는 `crop: false` | 필터를 바꿔도 상자가 움직이지 않는다 |
| L9 | 사용자 `layout` 좌표는 아직 반영하지 않는다 | 수동 배치와 재라우팅은 M3 |

테스트가 보장하는 성질: 결정성, 상자 겹침 없음, 모든 선분 수평·수직, 선이 상자를 관통하지 않음,
서로 다른 넷의 선분이 겹치지 않음, 각 넷이 드라이버와 모든 싱크를 실제로 연결, 팬아웃에 접점.

## 계층과 접기 — 루트·schematic 파일 (M6.5 앞당김)

| # | 결정 | 이유 |
|---|---|---|
| H1 | **파일 계층** — 프로젝트 폴더에 루트 `<top 모듈>.rtlgraph.json`(전역), 컴포넌트 폴더마다 `<컴포넌트 이름>.rtlgraph-schematic.json`(항상), 상태 기계가 필요한 컴포넌트만 `<컴포넌트 이름>.rtlgraph-fsm.json`. 자식 안에 자식이 있을 수 있어 재귀적이고, 루트만 schematic 이 없는 예외 | 사용자 결정(2026-09-14). 단일 컴포넌트도 main component 폴더(`demo/acc/acc/`) |
| H2 | 루트는 `kind: "system"` — 포트와 `component` 노드만. 논리 노드가 있으면 에러 `system-logic`. 탑이 자기 레지스터·논리를 가지면 탑이 곧 main component 이고 루트는 그것을 감싼 상자 하나 | 전역 파일은 요약이다. 논리는 schematic 한 곳에만 있다(D9 와 같은 이유) |
| H3 | `component` 노드 = `name`(식별자) · `module` · `ref`(이 파일 기준 `*.rtlgraph-schematic.json` 경로) · `ports` · 선택 `params`/`consts`. `flow`/`time` 없음. 상자와 파일의 포트가 다르면 `hierarchy-ports` 에러, 모듈 이름이 다르면 `hierarchy-module` 경고 | 상자는 자식 파일에서 파생 가능하지만, 접힌 상태로 그리려면 파일을 안 열고도 핀이 필요하다. 대신 일치를 검사한다 |
| H4 | `loadHierarchy(root, read)` 는 순수 함수 — 웹뷰·검증기·Export·CLI 가 같이 쓴다. 자식 경로·인스턴스 경로(`u_host/u_dma`)를 붙이고, 순환·깊이 16 초과·없는 파일을 진단한다. **깨진 자식은 상자만 접힌 채 남고** 루트가 깨졌을 때만 그리지 않는다 | 한 파일의 실수로 전체 그림이 사라지지 않게 |
| H5 | 펼친 컴포넌트는 **틀(frame)** — 아래에서 위로 배치: 자식을 먼저 배치하고 부모는 그 크기의 상자로 배치한다. 틀의 핀은 자식 포트의 y 에 둔다 | 부모 배선이 틀 안을 지나지 않고, 틀 가장자리에서 자식 포트까지 직선 연결 |
| H6 | 틀 안의 포트는 **가장자리** — 입력은 행 맨 왼쪽, 출력은 전체 오른쪽 끝에 정렬, 같은 행의 포트는 세로로 쌓아 핀마다 y 가 다르다. 단 입력이 제어 블록 하나의 핀으로만 가면 그 핀 옆에 붙인다 | 같은 y 의 핀 두 개가 부모에서 겹쳤다(테스트가 잡음). 제어 입력이 채널을 크게 돌던 모양 제거 |
| H7 | 렌더러는 자식 요소 ID 에 인스턴스 경로를 붙인다(`acc/CNT_FF`, `acc/ACC_D`). 접힌 상자는 `+`, 틀은 `−` 표시. 필터는 모든 층과 연결선에 적용 | 컴포넌트 ID = 인스턴스 경로라 선택·접기 상태가 그대로 이 ID 를 쓴다 |
| H8 | **접기 동작** — 아무것도 선택하지 않으면 계층 전체를 접고/편다. 컴포넌트를 선택하면 "그것만" 또는 "그 안의 자손까지" 를 고른다(Quick Pick). 하나를 접어도 안쪽의 펼침 상태는 기억하고, 깊은 것을 펴면 바깥도 함께 편다. 더블클릭은 그 상자만 토글 | 사용자 결정(NodeGraph 의 fold/unfold 참고) |
| H9 | 접기 상태는 **JSON 이 아니라** 웹뷰 state + 파일별 `workspaceState`(E3 와 같음). 기본값: 컴포넌트 하나를 감싼 루트는 그것을 펼치고, 나머지는 접힘. Export 는 현재 접기 상태를 그린다 | 보기만 해도 파일이 바뀌면 안 된다. 단일 컴포넌트 루트를 열면 곧바로 회로가 보인다 |
| H10 | 호스트가 루트에서 닿는 schematic 을 모두 읽어(열린 편집기의 미저장 내용 우선) 웹뷰로 한 번에 보내고, 파일 감시로 자식 변경도 즉시 반영한다 | 웹뷰는 파일을 못 읽는다(E2 유지). 에이전트가 자식만 다시 써도 갱신 |
| H11 | e2e 는 루트를 연다 — 펼친 상태·필터·접기 범위·재오픈 후 유지·자식 파일 열기. Export 는 사용자 폴더를 지우지 않도록 `.out-e2e-${name}` 에 쓴다 | `demo/acc/.out-acc_top/` 는 사용자가 직접 뽑은 결과물 |
| H12 | FSM 파일은 다음 단계 — 상태도 + 표 보기, 상태 의미와 전이 조건은 문법이 아닌 **의미 수준으로 추상화**, `moore`/`mealy` 명시. 스펙은 아직 쓰지 말라고 한다 | 사용자 목표(2026-09-14) |
| H13 | 폴더 구조가 없는 코드에서는 **상태(레지스터)를 가진 프로젝트 모듈 = 컴포넌트**, 상태 없는 모듈은 기존대로 평탄화(또는 `control` 노드). 같은 모듈의 여러 인스턴스는 schematic 하나를 함께 가리킨다 | 핵심 사용 사례(기존 RTL)는 대개 `seq/` 폴더가 없어, "자기 `seq/` 를 가진 폴더" 규칙만으로는 계층이 전혀 생기지 않았다 |
| H14 | 루트에는 **항상 main component 상자 하나**. 탑이 컴포넌트 배선뿐이어도 그 상자들은 main component schematic 안에 둔다. `source.root` 는 schematic 폴더에서 코드 폴더까지의 경로 | 루트 규칙이 두 갈래라 "main component 폴더는 항상" 과 충돌했다. 에이전트마다 다르게 해석할 여지를 없앤다 |
| H15 | 틀 안에서 제어 블록 핀 옆에 붙는 입력이 있으면, 그 행으로 가던 다른 입력 포트는 **한 행 아래**에 둔다 | 새 세션이 만든 `demo/updown` 에서 `DIN` 이 제어 블록 행에 쌓여 부모의 `UP`·`DIN` 포트가 겹쳤다. 붙이기를 끄면 제어선이 크게 돌아 읽기 어려웠다 |
| H16 | 프롬프트 검증은 **새 `claude -p` 세션**으로 한다 — demo 를 스크래치에 복사, Copy Agent Spec 이 쓰는 파일만 넣고 프롬프트 경로를 채워 실행, RTL md5·검증기·펼친 렌더·최종 보고를 확인 | 서브에이전트는 대화는 모르지만 같은 세션의 도구·환경을 쓴다. 사용자가 실제로 겪는 조건과 같게 |

## 개발 환경

- Node 22 의 타입 스트리핑 + `node:test`. 의존성은 `typescript`, `@types/node` 뿐.
- `erasableSyntaxOnly` 로 enum/namespace 같은 런타임 TS 문법을 막는다.
- NodeGraph 교훈에 따라 `node_modules/`, `dist/`, `*.vsix` 는 처음부터 ignore.
- 골든 SVG(`demo/acc/*.svg`)는 의도한 시각 변경 후 `npm run golden` 으로 갱신한다.
